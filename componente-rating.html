Rating (Rating, Info Rating)

O Rating deixa o usuário dar uma nota tocando num ícone, com estrelas ou com rostos de muito triste a muito feliz, como em "Como foi seu atendimento?". O Info Rating só mostra uma nota com estrelas, para leitura, como a média de avaliações de um produto.

Componentes

Resumo

Rating

Avaliação em que o usuário escolhe uma nota tocando num ícone, como "Como foi seu atendimento?". Há dois tipos: quantitativo, com estrelas (a nota preenche as estrelas até a escolhida), e qualitativo, com 5 rostos que vão de muito triste a muito feliz (só o rosto escolhido fica destacado).

InfoRating

Mostra uma nota com estrelas, só para leitura, como a média de avaliações de um produto. O usuário não interage com ela. Aceita meia estrela.

Regras que não aparecem no Figma (pontos de atenção no handoff)

InfoRating

  • ⚠️ Meia estrela: se o design mostra meia estrela, avise no handoff para usar withHalfValue. Sem ela, o código arredonda a nota.
  • ⚠️ Nota exata: informe de onde vem a nota (ex.: média das avaliações) e com quantas casas decimais.
  • ⚠️ Dev Mode: o trecho de código é sempre <InfoRating value={3} />, fixo. No Mobile, o Info Rating não tem trecho de código.

Rating

  • ⚠️ Tamanho no desktop: o Figma Desktop usa ícones de 24px com 8px de espaço, mas o código usa 32px com 16px por padrão. Informe o tamanho desejado (size). O espaço de 16px não muda.
  • ⚠️ Avaliação de positivo e negativo: não existe no Figma. Para desenhar, troque os ícones à mão e informe no handoff os ícones, as cores e o texto de cada opção para o leitor de tela (valueLabels).
  • ⚠️ Dev Mode no Mobile: o trecho de código do Rating mostra <InfoRating value={3} />, porque a ligação do Mobile aponta para o componente errado. O certo é o Rating. No Desktop, o trecho mostra type e disabled conforme o design.

valueLabels"muito ruim", "ruim", "regular", "bom", "muito bom" (qualitativo com os rostos padrão) ou "1 de 5", "2 de 5"…♿ Texto lido pelo leitor de tela em cada ícone, na ordem. Os textos precisam ser diferentes entre si.²

¹ ℹ️ Nota controlada ou não: com value, quem usa o componente guarda a nota e precisa atualizá-la no onChangeValue; sem ela, a avaliação começa no defaultValue (ou sem nada marcado) e troca sozinha. Valores fora do intervalo são ajustados para 0 ou para o total de ícones.

² ⚠️ Textos repetidos em valueLabels: por dentro, cada ícone é uma opção de um grupo de radio, e o texto é o valor dela. Dois textos iguais fazem as duas opções se confundirem.

⚠️ Dentro de um Form: o Rating não tem name. O grupo interno usa o nome fixo info-rating, e o valor guardado no formulário é o texto do valueLabels (ex.: "bom"), não o número. Dois Ratings no mesmo Form usam o mesmo nome. Use o onChangeValue para pegar a nota.

ℹ️ Ícones próprios no qualitativo: a lista icons pode ter qualquer quantidade de opções, não só 5. Dá para fazer, por exemplo, uma avaliação de positivo e negativo com dois ícones de polegar (ver o segundo exemplo abaixo). A nota devolvida é a posição do ícone na lista (1 para o primeiro, 2 para o segundo).

⚠️ Com icons próprios, passe valueLabels: os textos padrão dos rostos ("muito ruim" a "muito bom") só valem com os rostos padrão. Com outros ícones, o código usa os textos do quantitativo calculados pelo count, que continua 5: com dois ícones, o leitor de tela leria "1 de 5" e "2 de 5". Passe um texto para cada ícone (ex.: ['Não gostei', 'Gostei']). Não use count para corrigir isso: no qualitativo, o TypeScript não aceita count (dá erro de tipo) e, mesmo que funcione na tela, o leitor de tela leria só "1 de 2" e "2 de 2", sem dizer o que cada opção significa.

ℹ️ Interação: passando o mouse, os ícones mostram a prévia da nota. Pelo teclado, a avaliação funciona como um grupo de radio: as setas mudam a nota.

ℹ️ Cores: no quantitativo, as estrelas marcadas usam a cor de controle ativo e as desmarcadas, a cor de controle. No qualitativo, cada rosto marcado tem sua cor (do vermelho ao verde). Sobre fundos brand e negative, todos usam as cores próprias desses fundos.
