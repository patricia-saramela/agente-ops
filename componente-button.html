Button (Button, Button Link, Icon Button, Toggle Icon Button)

Os botões executam uma ação ou levam a outra página. Há botões com texto (primário, secundário e de perigo), o Button Link, com cara de link, e os botões só de ícone (Icon Button e Toggle Icon Button, que alterna entre ligado e desligado). Use o primário para a ação principal da tela, o secundário para as alternativas e o de perigo para ações destrutivas.

Componentes

Resumo

ButtonPrimary / ButtonSecondary / ButtonDanger

Botões de ação com texto. Podem executar uma função, navegar para outra página, enviar um formulário ou apenas ter a aparência de botão dentro de uma área que já é clicável.

  • ButtonPrimary
  • ButtonSecondary
  • ButtonDanger

Os três têm as mesmas props.

ButtonLink

Botão com aparência de link de texto, sem fundo nem borda. Usado para ações de menor destaque ou para navegar (ex.: "Ver todos", "Saiba mais").

IconButton

Botão que mostra só um ícone, sem texto. Usado para ações rápidas e reconhecíveis pelo ícone (fechar, compartilhar, excluir).

ToggleIconButton

Botão de ícone que alterna entre dois estados, ligado e desligado (ex.: favoritar / desfavoritar). Cada estado tem seu próprio ícone, cor e rótulo.

Regras que não aparecem no Figma (pontos de atenção no handoff)

ButtonLink

  • ⚠️ Seta de navegação: no código, todo link que leva para outra página (to ou href) mostra a seta (›) depois do texto, a menos que ela seja desligada. Indique no handoff se o link deve ou não ter a seta.
  • ⚠️ Formulários: o ButtonLink não envia formulários (não aceita submit). Para enviar, use um botão.
  • ⚠️ Dev Mode: o trecho de código que o Figma mostra no Dev Mode sempre usa ButtonLink, mesmo com Type=Danger ou Neutral. A ligação de código do ButtonLinkDanger aponta para um componente que não existe mais no Figma.
Combinações de propriedades: o que o código faz

Nenhuma combinação de variantes do Figma conflita com o código.

Button

  • ⚠️ Carregando automático: no código, o botão mostra o spinner sozinho enquanto a ação do clique ou o envio do formulário está em andamento. Dentro de um formulário, todos os botões ficam desabilitados durante o envio.
  • ⚠️ Ícones dos dois lados: o Figma só permite um ícone por vez. Se o design precisar de ícone antes e depois do texto, desenhe à parte e indique no handoff.
  • ⚠️ Dev Mode no Mobile: a ligação de código do Figma Mobile que deveria ser do Button Primary aponta para o Button Danger. Por isso, o trecho de código que o Dev Mode mostra para o Button Danger no Mobile usa ButtonPrimary. Confira o componente certo no handoff.

IconButton

  • ⚠️ Texto para o leitor de tela: o botão não tem texto visível, então o código exige um rótulo para acessibilidade. Informe no handoff o que cada botão faz (ex.: "Fechar", "Compartilhar").
  • ⚠️ Área de toque: em telas sensíveis ao toque, o código garante uma área de toque mínima de 48px, mesmo no botão pequeno. Deixe espaço suficiente em volta dos botões pequenos.
  • ⚠️ Dev Mode: o trecho de código que o Figma mostra no Dev Mode sempre traz aria-label="icon button". Troque pelo texto certo no handoff.
Combinações de propriedades: o que o código faz

Nenhuma combinação de variantes do Figma conflita com o código.

ToggleIconButton

  • ⚠️ Aparência de cada estado: informe o ícone, a cor (Type) e o tipo de fundo (Background type) do estado ligado e do desligado. Para isso, dá para usar o Icon Button do Figma, que tem essas propriedades.
  • ⚠️ Texto para o leitor de tela: informe o texto de cada estado, descrevendo a ação (ex.: "Adicionar aos favoritos" e "Remover dos favoritos").
  • ⚠️ Fundo: o Toggle Icon Button não tem Theme context no Figma. No código, ele muda de cor sozinho conforme o fundo onde está.
  • ⚠️ Dev Mode: o trecho de código que o Figma mostra no Dev Mode vem sem ícones e com rótulos genéricos ("checked" e "unchecked"). Complete no handoff.

Dúvidas reais respondidas pelo suporte

Dúvida: Quando usar a opção de navegação (chevron) no Button Link? Resposta: O chevron do Button Link é só para navegação. Em ações (ex.: "Cancelar", "Limpar filtros"), não use chevron. Vale em qualquer contexto: button fixed, sheet ou modal.

Ref. #16 · 05/2024

Dúvida: No botão com loading, é preciso usar reticências ("Enviando...")? Resposta: Não são obrigatórias. Pode usar só spinner + texto (o guia de conteúdo recomenda evitar reticências).

Ref. #26 · 07/2024

Dúvida: Como fazer o Button Link com o chevron pequeno certo? Resposta: Nas propriedades do Button Link, ative navigation: ela puxa o chevron correto do componente. Não use um chevron avulso da biblioteca de ícones.

Ref. #36 · 10/2024

Dúvida: No hover, o Button Link parece desalinhar do grid. Está certo? Resposta: Sim. O hover aparece muito rápido (no mobile mais ainda); na maior parte do tempo o botão fica no estado inicial, que é o alinhado. Não precisa alinhar o hover ao texto.

Ref. #143 · 02/2025

Dúvida: O loading do Button Link desalinha o botão. Dá para alinhar à esquerda ou pôr o loading à direita? Resposta: Use a propriedade bleedLeft (existe no Figma e no código) para alinhar o Button Link ao conteúdo. A posição do loading é padrão (centralizada na área do botão) e não pode ser mudada. Dúvidas de implementação: o dev deve usar o canal de suporte de desenvolvimento do Design System.

Ref. #156 · 02/2025

Dúvida: Para editar informação, uso Icon Button de editar ou Button Link "Editar xxx"? Resposta: Para editar um único campo, use o botão com ícone de editar. Para editar um bloco de informações, use o Button Link "Editar xxx".

Ref. #902 · 03/2026

Dúvida: Há botão flutuante com notificação (ex.: chat minimizado)? Resposta: Não há componente exato. Havia uma iniciativa semelhante (botão flutuante de IA) na nova versão do app: envolva Pesquisa e Evolução para convergir as soluções. A solução adotada foi IconButton + Badge, construída de forma atômica no Figma (o Icon Button não aceita Badge nativamente).

Ref. #1211 · 08/2026

Dúvida: Que hierarquia de botão usar em listagens extensas (ex.: "Pagar fatura" e "Mostrar assinatura")? Resposta: Escolha pela importância da ação, não pela aparência. Primário para a ação principal e transacional (ex.: pagar); secundário para ação de menor ênfase; Button Link para consulta ou navegação (ex.: ver detalhes), o que evita peso visual excessivo. Não equalize botões de ações semanticamente diferentes só para ficarem iguais. Para um padrão entre jornadas, valide com Pesquisa e Evolução.

Ref. #1222 · 08/2026

Dúvida: O botão em dev tem padding diferente do Figma e o texto quebra em alguns aparelhos. Resposta: No Storybook não há esse padding extra, e os botões não quebram: o texto do label fica com reticências. Verifique se o dev fez alterações manuais.
