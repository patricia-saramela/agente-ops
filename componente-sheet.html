Sheet

O Sheet é um painel que, no celular, sobe da parte de baixo da tela, e no desktop aparece como uma janela no centro. Use para escolher uma opção, mostrar ações ou um conteúdo curto sem sair da tela; os tipos prontos abrem por código, e o Sheet com conteúdo livre é montado à mão.

Parte 5 · Referência por componente

Cada página de componente tem: Resumo; Regras que não aparecem no Figma; Comportamento no código (o que acontece de fato na tela); No Figma (propriedades e diferenças Desktop × Mobile); e Dúvidas reais respondidas pelo suporte. Legenda: 🎨 muda o visual; ♿ acessibilidade; ⚠️ ponto de atenção; ℹ️ informação.

Componentes

Resumo

Sheet / SheetBody / SheetRoot: Slot (Only web)

Painel com conteúdo livre, montado à mão quando os tipos prontos do showSheet não bastam (ex.: um formulário curto). No celular, sobe a partir da parte de baixo da tela; no desktop, aparece como uma janela no centro. No Figma, é o Sheet dialog com Type=Slot (Only web).

  • Sheet: a moldura do painel (fundo escuro, animação, botão X, arrastar para fechar). Coloque-o na tela quando quiser abrir o sheet e tire-o no onClose.
  • SheetBody: o conteúdo padrão dentro do Sheet: título, subtítulo, descrição, conteúdo livre e botões no rodapé.
  • SheetRoot: precisa estar montado uma vez no app para o showSheet funcionar. Não é usado pelo Sheet montado à mão.

Sheet: Action list (ACTIONS_LIST)

Painel com uma lista de ações para o usuário escolher uma, como "Editar", "Compartilhar" e "Excluir". No celular, sobe a partir da parte de baixo da tela; no desktop, aparece como uma janela no centro. No Figma, é o Sheet dialog com Type=Action list.

ℹ️ Não existe um componente para colocar na tela: o sheet é aberto por código, com showSheet({type: 'ACTIONS_LIST', props: {...}}). A função devolve uma Promise com a ação escolhida.

Sheet: Actions (ACTIONS)

Painel com um texto e botões para o usuário decidir, como "Deseja salvar as alterações?". No celular, sobe a partir da parte de baixo da tela; no desktop, aparece como uma janela no centro. No Figma, é o Sheet dialog com Type=Actions.

ℹ️ Não existe um componente para colocar na tela: o sheet é aberto por código, com showSheet({type: 'ACTIONS', props: {...}}). A função devolve uma Promise com o botão apertado.

Sheet: Informative (INFO)

Painel que mostra uma lista de informações, cada uma com ícone ou marcador, título e descrição, como as vantagens de um plano. Não pede escolha: o usuário só lê e fecha. No celular, sobe a partir da parte de baixo da tela; no desktop, aparece como uma janela no centro. No Figma, é o Sheet dialog com Type=Informative.

ℹ️ Não existe um componente para colocar na tela: o sheet é aberto por código, com showSheet({type: 'INFO', props: {...}}). A função devolve uma Promise que termina quando o sheet fecha.

Sheet: Single selection (RADIO_LIST)

Painel com uma lista de opções em que o usuário escolhe uma, como "Escolha a forma de pagamento". No celular, sobe a partir da parte de baixo da tela; no desktop, aparece como uma janela no centro. No Figma, é o Sheet dialog com Type=Single selection.

ℹ️ Não existe um componente para colocar na tela: o sheet é aberto por código, com showSheet({type: 'RADIO_LIST', props: {...}}). A função devolve uma Promise com a escolha do usuário.

Regras que não aparecem no Figma (pontos de atenção no handoff)

Sheet

  • ⚠️ Ícones no Action list e no Single selection: o código não aceita ícone do Design System nem avatar, só imagens redondas por endereço (40px, ou 24px no Single selection com size: 'small'). Se o design precisar de ícones do Design System, há duas saídas: o Sheet montado à mão (Slot (Only web)), com uma lista de Row com ícones, que perde o visual nativo no app; ou o Menu, cujo item aceita ícone do Design System e a variação destrutiva.
  • ⚠️ Filtros: Single Filter e Multiple filter não existem no código. Combine com o desenvolvimento: dá para montar com o Sheet à mão, que é só web.
  • ⚠️ Dentro do app: com o visual nativo ligado, os tipos do showSheet aparecem no visual do sistema (iOS/Android), não no do Figma. O Slot (Only web) sempre aparece no visual web.
  • ⚠️ Single selection: no celular não há botão; tocar na opção já confirma e fecha. No desktop, o texto do botão é sempre o do tema ("Continuar").
  • ⚠️ Título: fica em uma linha só no código. Evite títulos longos.
  • ⚠️ Fechar: o sheet fecha pelo X, tocando fora e, no celular, arrastando para baixo. A tecla Esc não fecha.
  • ⚠️ Dev Mode: no Desktop, o trecho de código é sempre o Sheet com o SheetBody e textos fixos, qualquer que seja o Type; não mostra o showSheet. No Mobile, o trecho mostra <SheetWeb />, um componente que não é exportado pelo Design System.

No Figma: propriedades e diferenças Desktop × Mobile

Sheet

Figma:

  • Sheet com o fundo da tela: biblioteca Desktop › Sheet [D] · biblioteca Mobile › Sheet
  • Painel: biblioteca Desktop › Sheet dialog · biblioteca Mobile › _resources/Sheet Dialog

ℹ️ O Sheet [D] (Desktop) e o Sheet (Mobile) mostram a tela escurecida com o painel por cima. O painel é a instância interna Sheet dialog (Desktop) ou _resources/Sheet Dialog (Mobile), onde ficam Type, Title, Subtitle, Description e Action. As linhas de cada lista são instâncias próprias: _resources/Sheet Row (Single selection), _resources com _resources/List asset (Informative) e _resources/Sheet_Action (Action list).

Dúvidas reais respondidas pelo suporte

Dúvida: Ao ativar o slot de uma Row dentro do Page Sheet e colocar uma List, o Figma dá erro. Resposta: Um componente não pode ser colocado dentro dele mesmo: a List é feita de Rows, então não dá para pôr Row dentro de Row. O Page Sheet é formado por Accordions, e dentro do Accordion é possível colocar List/Row.

Ref. #10 · 04/2024

Dúvida: O Sheet não está sobrepondo o header (navbar) no app. Resposta: Como a navbar e a tab bar do app são nativas, o Sheet dentro da webview fica por baixo delas. É preciso usar o Sheet da bridge nativa do app. Para dúvidas de desenvolvimento, o dev deve procurar o canal de suporte de desenvolvimento do Design System; o suporte de Ops cobre só a camada de design.
