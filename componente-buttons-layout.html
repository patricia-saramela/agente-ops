Buttons layout (Button Layout, Button Group, Fixed Footer)

Os componentes de Buttons layout organizam até três ações (botão primário, secundário e link) com o espaçamento e o alinhamento padrão. Use o Button Layout no rodapé de telas, formulários e modais, o Button Group no fim de cards e seções, e o Fixed Footer quando os botões precisam ficar presos na parte de baixo da tela.

Componentes

Resumo

ButtonLayout

Organiza até três ações (um botão primário, um secundário e um link) com o espaçamento e o alinhamento padrão do Design System. Usado no rodapé de telas, formulários e modais. É a base usada pelo Dialog, Drawer, Sheet e ButtonFixedFooterLayout.

ButtonFixedFooterLayout

Versão pronta do FixedFooterLayout para rodapés com botões. Recebe os botões e já monta o rodapé com o espaçamento certo, usando um ButtonLayout com alinhamento full-width.

ButtonGroup

Agrupa até três ações (um botão primário, um secundário e um link) com o espaçamento e o alinhamento padrão do Design System. Usado no fim de cards, seções ou formulários.

FixedFooterLayout

Layout de página com um rodapé fixo na parte de baixo da tela, enquanto o conteúdo rola por trás. Use quando uma ação precisa ficar sempre visível (ex.: "Continuar" em um fluxo). Para o caso mais comum, rodapé só com botões, prefira o ButtonFixedFooterLayout.

Regras que não aparecem no Figma (pontos de atenção no handoff)

ButtonFixedFooterLayout

  • ⚠️ Largura dos botões: no código, os botões ocupam toda a largura no celular e no tablet; no desktop, ficam alinhados à esquerda.
  • ⚠️ Desktop: o rodapé só fica fixo no celular e no tablet. No desktop, aparece logo depois do conteúdo.
  • ⚠️ Botão de perigo: os dois botões podem ser ButtonDanger no código. Se o design usar o botão de perigo, indique no handoff.

FixedFooterLayout

  • ⚠️ Telas baixas: se sobrar menos de 200px acima do rodapé, ele deixa de ser fixo e rola junto com o conteúdo.
  • ⚠️ Só botões: para um rodapé só com botões, prefira o Button Fixed Footer Layout.

Dúvidas reais respondidas pelo suporte

Dúvida: Os botões fixos de ação (ex.: no Feedback) devem ter sombra? Resposta: O Design System não define. Fica a critério do time; a recomendação de UX é usar sombra quando o conteúdo passa da altura da tela e rola por trás dos botões fixos.

Ref. #17 · 06/2024

Dúvida: Usa chevron no botão secundário? Resposta: Não. No Button Fixed Footer Layout há três variações (Primary, Secondary e Button Link) e nenhuma usa chevron quando estão dentro dele, mesmo que o link leve o usuário para fora da jornada. Isso mantém a consistência entre app e web.

Ref. #20 · 06/2024

Dúvida: Dá para usar loading no botão do Button Fixed Footer Layout? Resposta: Sim. Nas propriedades do botão, ative o estado Loading.

Ref. #21 · 06/2024

Dúvida: No (Button) Fixed Footer Layout, o botão tem largura fixa ou se adapta ao texto? Resposta: Os botões têm largura Hug (se adaptam ao texto), no desktop e no mobile.

Ref. #29 · 07/2024

Dúvida: Pode usar três botões (Primary, Secondary e Link) no Side Drawer? O Button Link leva chevron? Resposta: O Side Drawer usa o Button Group do Design System. No desktop, é possível usar as três hierarquias. No mobile, as combinações permitidas são: Primary; Primary + Secondary; Primary + Link; Secondary; Secondary + Link; Link. Avalie como a solução fica no mobile. O uso do chevron no Button Link segue o guia do arquivo Master B2C.

Ref. #87 · 12/2024

Dúvida: O Fixed Footer segue a largura da tela (ex.: tablet acima de 1024px mostra botões lado a lado)? E o espaçamento? Resposta: Sim, o componente segue o tamanho da tela automaticamente. Como a versão desktop não traz espaçamento embutido entre o conteúdo e os botões, indique no handoff o espaçamento necessário, seguindo o guia de fundamentos (aplicação de tokens de espaçamento).
