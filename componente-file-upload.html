File Upload

O File Upload deixa o usuário escolher um ou mais arquivos do aparelho, como documentos ou fotos, e mostra a lista do que foi escolhido. Use quando o fluxo pede um anexo; com a área de soltar (drop zone), também dá para arrastar arquivos no desktop.

Campos de formulário

Resumo

FileUpload

Componente para o usuário escolher um ou mais arquivos do aparelho (documentos, fotos, vídeos). Mostra um ícone, um título, uma descrição e um botão que abre o seletor de arquivos do sistema. Com withDropZone, vira uma área com borda tracejada onde também dá para arrastar e soltar arquivos. Os arquivos escolhidos aparecem numa lista embaixo (cada um num FileItem), com nome, tamanho e um botão para remover.

O componente tem dois modos:

  • Padrão (com renderButton): o Design System monta a área, o texto, o botão e a lista. Quem usa escolhe o botão e pode trocar a lista (renderFiles).
  • Livre (com render): quem usa desenha tudo. O componente só entrega os arquivos e as funções para abrir o seletor, arrastar e remover (ex.: uma galeria de fotos).

FileItem

Linha que mostra um arquivo escolhido: miniatura ou ícone do tipo de arquivo, nome, tamanho e um botão ✕ para remover. É o item da lista padrão do FileUpload e pode ser usado numa lista própria (no renderFiles), dentro de um BoxedRowList.

Regras que não aparecem no Figma (pontos de atenção no handoff)

FileItem

  • ⚠️ Nome e tamanho: vêm do arquivo escolhido. Não é preciso informar no handoff, mas use exemplos reais (ex.: fatura-outubro.pdf, 230 KB).
  • ⚠️ Imagens: no código, imagens aparecem como miniatura. Não use o ícone jpg ou png no design.
  • ⚠️ Arquivos psd: hoje aparecem com o ícone de clipe no código. Se o design depende do ícone de Photoshop, avise o time de desenvolvimento.
  • ⚠️ Sem Code Connect: o Dev Mode não mostra o código do FileItem.

FileUpload

  • ⚠️ Sem Code Connect: o Dev Mode não mostra o código do FileUpload. Diga no handoff o botão usado, se tem área de arrastar e os textos.
  • ⚠️ Variante habilitada sem área de arrastar: no Figma, ela se chama Disabled=True. Confira o visual, não o nome, e diga no handoff se o componente fica desabilitado.
  • ⚠️ Regras dos arquivos: informe os tipos aceitos (ex.: "PDF ou JPG"), se pode mais de um arquivo, se os novos se somam aos que já estavam e o tamanho máximo. O código não valida tamanho nem quantidade sozinho.
  • ⚠️ Mensagens de erro: informe cada mensagem (ex.: "O arquivo passa de 10 MB", "Tipo de arquivo não aceito"). Arquivos arrastados não passam pelo filtro de tipo, então a mensagem de tipo errado também é preciso.
  • ⚠️ Estados automáticos: Hover e Dragover acontecem sozinhos no código. Não é preciso marcar quando usar cada um.

Comportamento no código (versão 18.0.0)

Tabelas de propriedades sem as props só técnicas. "Padrão" é o valor usado quando nada é informado.

FileUpload

Propriedades
PropValores aceitosPadrãoDescrição
renderButton (obrigatória)Desenha o botão que abre o seletor (ex.: ButtonPrimary, ButtonSecondary ou IconButton). Repasse todas as props recebidas para o botão. O botão é sempre pequeno (small). Só no modo padrão.
render (obrigatória)Desenha o componente inteiro. Recebe os arquivos e as funções para abrir o seletor (openFileDialog), remover (removeFile), trocar a lista (setFiles) e montar uma área de arrastar (dropZoneProps, isDragActive). Só no modo livre.²
withDropZonesim/nãofalseTransforma o conteúdo numa área com borda tracejada, centralizada, onde dá para arrastar e soltar arquivos. A área toda abre o seletor ao clicar. Só no modo padrão.³
assetÍcone ou imagem acima do título (ex.: <IconExportRegular color="currentColor" />). A cor muda com o fundo. Só no modo padrão.
titleTítulo (ex.: "Arraste ou escolha o seu arquivo"). É o rótulo do campo para o leitor de tela. Só no modo padrão.
descriptionTexto embaixo do título, na cor secundária (ex.: "PDF ou JPG, até 50 MB"). Só no modo padrão.
slotConteúdo livre entre a descrição e o botão. Só no modo padrão.
renderFilesTroca a lista padrão de arquivos por uma lista própria. Só no modo padrão.
acceptTipos de arquivo aceitos no seletor (ex.: 'image/*', '.pdf,.docx').⁵
multiplesim/nãoPermite escolher mais de um arquivo de uma vez. Sem ela, ao soltar vários arquivos, só o primeiro fica.⁶
allowAppendsim/nãofalseOs arquivos novos se somam aos que já estavam. Sem ela, cada escolha substitui a lista.⁶
captureboolean | 'user' | 'environment'No celular, abre direto a câmera: 'user' para a câmera frontal e 'environment' para a traseira.
disabledsim/nãofalseDesabilita o componente: fica esmaecido, o botão fica desabilitado e não dá para arrastar nem remover arquivos.
errorTextMensagem de erro embaixo do conteúdo, em vermelho com um ícone de alerta. O componente não valida nada sozinho: quem usa decide quando mostrar.⁷

¹ ℹ️ Modo: use uma, e só uma, entre renderButton (modo padrão) e render (modo livre). Com render, as props marcadas como Só no modo padrão não são aceitas.

² ℹ️ Modo livre: para a área de arrastar funcionar, espalhe o dropZoneProps no elemento da área (<div {...dropZoneProps}>) e use o isDragActive para mudar o visual enquanto o arquivo está por cima. O rótulo precisa de htmlFor={id} para o leitor de tela.

³ ℹ️ Área de arrastar: com withDropZone, a área tem borda tracejada; ao passar o mouse e ao arrastar um arquivo por cima, a borda fica contínua e o fundo muda de cor. Enquanto o arquivo está por cima, o asset cresce um pouco. A área tem 32px de espaço interno em cima e embaixo e 24px dos lados (24px e 16px no celular e no tablet). Sem withDropZone, o conteúdo fica alinhado à esquerda, sem borda, e não aceita arrastar.

⁴ ⚠️ Como pegar os arquivos: o FileUpload não tem onChange e não entra nos values do Form do Design System. Os arquivos chegam ao renderFiles ou ao render (files), ou ficam no campo de arquivo com o name, para um envio de formulário comum (FormData).

⁵ ⚠️ accept e arrastar: o accept filtra só os arquivos do seletor. Arquivos arrastados para a área não são filtrados: se precisar, confira o tipo e mostre o errorText.

⁶ ⚠️ allowAppend sem multiple: com allowAppend e sem multiple, cada escolha adiciona mais um arquivo, então a lista pode ter vários arquivos.

⁷ ℹ️ Erro: o componente não tem limite de tamanho nem de quantidade. Valide os arquivos e passe a mensagem no errorText. A mensagem é anunciada pelo leitor de tela na hora.

ℹ️ Lista padrão: sem renderFiles, os arquivos aparecem numa lista (BoxedRowList) com um FileItem para cada um. Para o leitor de tela, a lista se chama "Arquivos enviados".

ℹ️ Cores: a cor do asset e a da borda da área de arrastar mudam com o fundo (default, alternative, brand, negative ou media).

ℹ️ Aparência: é um BoxedRow, então cada arquivo fica numa caixa. O botão ✕ é um IconButton pequeno.

ℹ️ Tamanho: o tamanho usa o separador decimal do idioma, com até 2 casas em MB.
