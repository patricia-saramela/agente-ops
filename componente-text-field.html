Text Field

O Text Field é o campo de texto padrão, com rótulo, texto de ajuda e mensagem de erro, e versões de várias linhas (textarea) e menor. Use para textos livres, como nome ou endereço; para dados com formato próprio (e-mail, telefone, senha, data), use o campo específico do Design System.

Campos de formulário

Resumo

TextField

Campo de texto com rótulo (label) que sobe para o topo do campo ao digitar, texto de ajuda e mensagem de erro embaixo. Funciona sozinho ou dentro de um Form, que guarda o valor pelo name e valida ao enviar. Também tem versão de várias linhas (multiline), sugestões enquanto o usuário digita (getSuggestions) e versão menor (small). Para campos com formato próprio (e-mail, telefone, senha, data…), use o campo específico do Design System.

TextFieldBase

⚠️ O TextFieldBase não é um componente de interface e não deve ser usado em telas. Ele é uma peça interna de desenvolvimento, usada só para criar um tipo de campo novo que o Design System não tem. Não existe no Figma e não aparece no design. Numa tela, use sempre o TextField ou o campo específico do tipo de dado (EmailField, PasswordField, PhoneNumberField, DateField etc.; ver a tabela em "Quando usar cada um").

Base visual de todos os campos de texto do Design System (TextField, EmailField, PasswordField, DateField etc.): a caixa com borda, o rótulo que sobe, o texto de ajuda e a mensagem de erro. Sozinho, não se liga ao Form: para criar um campo próprio que funcione com o formulário, use junto com o hook useFieldProps (ver hooks do Form). Para um campo de texto comum, use o TextField.

Regras que não aparecem no Figma (pontos de atenção no handoff)

TextField

  • ⚠️ Tipo de dado: use o componente do tipo de dado certo (Email Field, Phone Field, Date Field etc.). Se nenhum servir e o Text Field for usado, diga que dado o campo recebe.
  • ⚠️ Obrigatório ou opcional: diga quais campos são opcionais. No código, eles mostram "(opcional)" depois do rótulo, o que o componente do Figma não mostra.
  • ⚠️ Largura no desktop: o componente do Figma tem 496px, mas no código o campo tem 328px, a menos que ocupe a largura toda (fullWidth). Diga qual dos dois usar.
  • ⚠️ Erros: informe as regras de validação e o texto de cada mensagem de erro. Campo obrigatório vazio mostra "Este campo é obrigatório".
  • ⚠️ Estados: não precisa indicar Inactive, Focused ou Activated: no código, o estado muda sozinho conforme o usuário interage.
  • ⚠️ Dev Mode: o trecho de código segue o rótulo, o texto de ajuda, o Error, o Disabled, o Read only, o Multiline e o End icon do design. O name é sempre "text-field" e o Prefix não aparece.

TextField

Quando usar cada um

Use o TextField quando:

  • O campo recebe um texto livre, sem formato próprio: nome, endereço, complemento, número do pedido, uma mensagem (com multiline).
  • O campo precisa sugerir opções enquanto o usuário digita (com getSuggestions).

Use um campo específico do Design System, e não o TextField, quando o dado tem formato próprio. Ele já traz o teclado certo, a máscara e a validação:

DadoCampo
E-mailEmailField
SenhaPasswordField
TelefonePhoneNumberField ou PhoneNumberFieldLite
Número inteiro ou decimal (ex.: quantidade, valor)IntegerField ou DecimalField
Data, mês, horaDateField, MonthField, TimeField ou DateTimeField
BuscaSearchField
Cartão de créditoCreditCardNumberField, CreditCardExpirationField e CvvField (ou CreditCardFields)
Código de verificação (ex.: SMS)PinField
Lista de opçõesSelect

⚠️ Nunca use o TextFieldBase numa tela. Ele não é um componente de interface, e sim uma peça de desenvolvimento:

  • Serve só quando nenhum dos campos acima atende e é preciso criar um tipo de campo novo, com um comportamento que o Design System não tem (ex.: um campo de CEP com máscara própria). O TextFieldBase dá a aparência; o hook useFieldProps liga o campo ao Form.
  • Quem desenvolve cria o campo novo uma vez, a partir do TextFieldBase, e é esse campo novo que vai para as telas.

ℹ️ Para quem desenha: na tela, o TextField e o TextFieldBase são iguais. No Figma, a página Input fields tem um componente para cada campo específico (Text Field, Email Field, Password Field, Phone Field etc.), mas não tem o TextFieldBase: ele é só uma peça do desenvolvimento. Use no design o componente do tipo de dado certo e, quando nenhum servir, use o Text Field e diga no handoff que dado o campo recebe (ex.: "CEP", "valor em reais").

¹ ℹ️ Erro: o erro aparece de dois jeitos. Com error, o visual de erro é forçado por quem usa o campo. Dentro de um Form, o próprio formulário mostra o erro quando o campo obrigatório está vazio ("Este campo é obrigatório") ou quando o validate devolve uma mensagem. A mensagem aparece no lugar do helperText e é anunciada pelo leitor de tela na hora.

² ℹ️ Contador de caracteres: com multiline e maxLength, aparece embaixo, à direita, um contador como 12/200. O leitor de tela lê "12 de 200 caracteres".

³ ⚠️ Sugestões só no modo controlado: com getSuggestions, o campo precisa de value e não pode ter defaultValue. Sem isso, o componente dá erro e não aparece. A lista abre ao focar o campo e tem a largura do campo.

ℹ️ Rótulo: o rótulo fica no lugar do valor quando o campo está vazio e sem foco. Com foco ou valor, sobe e diminui. Clicar em qualquer parte do campo (no rótulo ou no prefixo) coloca o foco no texto.

ℹ️ Várias linhas: com multiline, o campo tem altura fixa. Ao receber o foco, o cursor vai para o fim do texto; ao perder o foco, a rolagem volta para o começo.

ℹ️ Cores: o campo tem sempre as cores do fundo padrão (fundo branco com borda), mesmo sobre fundos brand ou negative.
