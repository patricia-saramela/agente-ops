Form

O Form é o formulário que junta os campos do Design System, guarda o valor de cada um, valida tudo ao enviar e mostra os erros embaixo de cada campo. Use sempre que uma tela pede dados ao usuário e tem um botão de enviar; durante o envio, ele desabilita os campos e mostra um spinner no botão.

Padrões de tela

Resumo

Formulário que junta os campos do Design System (TextField, EmailField, Select, Checkbox, Switch etc.), guarda os valores de cada um pelo name, valida tudo ao enviar e mostra os erros embaixo de cada campo. Enquanto o envio acontece, os campos ficam desabilitados e o botão de enviar mostra um spinner. Para criar um campo próprio ou ler o estado do formulário, veja os hooks do Form.

¹ ℹ️ Valores:

  • values traz o valor tratado de cada campo (ex.: o número do cartão sem espaços, um número como number, um checkbox como true/false).
  • rawValues traz o valor exatamente como foi digitado.
  • Campos desabilitados ficam de fora dos dois.
  • Se onSubmit devolver uma Promise, o formulário fica no estado de envio até ela terminar.

² ℹ️ Erros para o leitor de tela: com mais de um campo com erro, o leitor de tela anuncia "Confira os seguintes erros:" seguido do nome (label) dos campos com erro. O getErrorMessageForScreenReader troca esse texto. Com um erro só, o leitor de tela lê o erro do próprio campo, que recebe o foco.

ℹ️ Ao enviar:

  1. Cada campo é validado: campo obrigatório vazio mostra "Este campo é obrigatório", e o validate de cada campo roda para os preenchidos. Campos desabilitados não são validados.
  2. Com erro, o envio para: o primeiro campo com erro recebe o foco e a página rola até ele, e o onValidationErrors é chamado.
  3. Sem erro, o onSubmit é chamado. Enquanto ele não termina, todos os campos, os checkboxes, os switches e os links de texto ficam desabilitados, e o botão com submit mostra o spinner.

ℹ️ Campos obrigatórios: dentro do Form, todo campo é obrigatório, a menos que tenha optional. Os campos também são validados ao perder o foco.

ℹ️ Botão de enviar: use um botão com a prop submit (ex.: <ButtonPrimary submit>). Ele envia o formulário ao ser clicado, e a tecla Enter num campo também envia.

⚠️ iOS: no iPhone e no iPad, quando o primeiro erro é numa lista (Select) ou num campo de data ou hora, o campo não recebe o foco (para não abrir o seletor do sistema sozinho), só a página rola até ele.

ℹ️ Aparência: o Form não tem aparência própria: o <form> só ocupa a largura toda, sem margem, espaçamento ou fundo. O espaço entre os campos vem de quem monta o formulário (ex.: um Stack). O que muda na tela durante o uso é o visual dos próprios campos e botões: o estado de erro, o desabilitado durante o envio e o spinner do botão de enviar.

⚠️ Validação do navegador: o Form desliga a validação própria do navegador (noValidate). Toda validação é a do Design System.
