Modal (Alert, Confirm, Dialog)

Os modais são janelas que abrem por cima da tela, com o fundo escurecido, e são abertos por código com o hook useDialog. Use o Alert para um aviso com um só botão, o Confirm para uma pergunta de sim ou não antes de uma ação, e o Dialog quando precisar de imagem, conteúdo extra ou mais botões. Só um modal pode estar aberto por vez.

Componentes

Resumo

Dialog

Janela modal completa, por cima da tela e com o fundo escurecido: pode ter imagem, título, subtítulo, mensagem, conteúdo extra, até dois botões, um link e sempre tem o botão X para fechar. Use quando o alert e o confirm não bastam, como para apresentar uma novidade ou pedir uma informação.

ℹ️ Não existe um componente para colocar na tela: o dialog é aberto por código, com a função dialog do hook useDialog. Só um modal (alert, confirm ou dialog) pode estar aberto por vez.

Alert

Janela modal com uma mensagem e um único botão (Aceitar), por cima da tela e com o fundo escurecido. Use para avisos que o usuário só precisa reconhecer, como "Sua sessão expirou".

ℹ️ Não existe um componente para colocar na tela: o alert é aberto por código, com a função alert do hook useDialog. Só um modal (alert, confirm ou dialog) pode estar aberto por vez.

Confirm

Janela modal com uma pergunta e dois botões (Aceitar e Cancelar), por cima da tela e com o fundo escurecido. Use para confirmar uma ação antes de executá-la, como "Excluir esta conta?".

ℹ️ Não existe um componente para colocar na tela: o confirm é aberto por código, com a função confirm do hook useDialog. Só um modal (alert, confirm ou dialog) pode estar aberto por vez.

Regras que não aparecem no Figma (pontos de atenção no handoff)

Alert

  • ⚠️ Dev Mode trocado no Desktop: o trecho de código do Alert [D] mostra confirm(...), e o do Confirm [D] mostra alert(...). As ligações de código estão invertidas. No Mobile estão certas.
  • ⚠️ Texto do botão no Dev Mode: o trecho sempre mostra acceptText: 'Accept', não o texto do design.
  • ⚠️ Dentro do app: informe se o alert vai aparecer no app. Lá o visual é o alerta do sistema (use os componentes iOS/Android para desenhar) e o botão de perigo não aparece.
  • ⚠️ Fechar: o alert não fecha ao clicar fora. Fechar com a tecla Esc conta como aceitar.

Confirm

  • ⚠️ Dev Mode trocado no Desktop: o trecho de código do Confirm [D] mostra alert(...), e o do Alert [D] mostra confirm(...). As ligações de código estão invertidas. No Mobile estão certas.
  • ⚠️ Textos dos botões no Dev Mode: o trecho sempre mostra acceptText: 'Accept' e cancelText: 'Cancel', não os textos do design.
  • ⚠️ Ação destrutiva: se o botão principal for de perigo (ex.: "Excluir"), avise no handoff: no Figma não há essa opção.
  • ⚠️ Dentro do app: informe se o confirm vai aparecer no app. Lá o visual é o alerta do sistema (use os componentes iOS/Android para desenhar).

Dialog

  • ⚠️ Mensagem obrigatória: no código não existe dialog sem mensagem. Se o design esconder a Description, combine com o desenvolvimento o texto que vai entrar.
  • ⚠️ Botões: indique quais botões e link aparecem e o que cada um faz; no código, cada botão só aparece se tiver ação.
  • ⚠️ Dev Mode: o trecho de código mostra props que não existem: extra (o certo é slot), showCancel e, no Mobile, forceWeb. Os textos dos botões são sempre "Accept"/"Cancel", o link é sempre o mesmo exemplo e o trecho não reflete a escolha de botões do design.
  • ⚠️ Fechar: o dialog fecha pelo X, pelo clique fora e pela tecla Esc, e todos contam como cancelar.

Dúvidas reais respondidas pelo suporte

Dúvida: O Dialog tem problemas de acessibilidade (fechar clicando no fundo, ações redundantes). O que usar para comunicar um erro? Resposta: Para erros e avisos de fluxo, use as telas de Feedback do Design System (Error Feedback e Info Feedback), que também têm versão desktop, em vez do Dialog. É o que o app usa.

Ref. #111 · 01/2025

Dúvida: O padding horizontal de 24px do Modal Confirm é mantido em qualquer largura de tela? Resposta: Sim, o padding de 24px não deve ser alterado.

Ref. #124 · 01/2025

Dúvida: Como implementar "Voltar" e "Fechar" juntos num modal do iOS? Resposta: O suporte não orienta código, mas há cenários no app iOS com modal que tem voltar e fechar ao mesmo tempo; use-os como referência para os devs.

Ref. #324 · 05/2025

Dúvida: Os modais de permissão de iOS e Android da biblioteca estão atualizados? Quais usar? Resposta: Use os da biblioteca do Design System: quando forem atualizados, seu arquivo também atualiza.

Ref. #625 · 10/2025

Dúvida: Há componente de "overflow menu" para compartilhar produto (biblioteca legada da loja)? Resposta: Foi definido usar os componentes da loja como estão, e o Modal recebeu melhorias planejadas: ligar/desligar botões e textos, slot para conteúdo customizado e botão de compartilhar (após validação de acessibilidade).

Ref. #933 · 03/2026

Dúvida: A squad diz que não pode usar modal numa tela informativa. Resposta: É mais uma limitação da arquitetura do app do que do componente. O dev deve procurar o canal de suporte de desenvolvimento. Se não for possível, a opção mais adequada é o bottom sheet.

Ref. #955 · 04/2026

Dúvida: Posso fazer um modal com imagem em tela cheia, incluindo a área da navigation bar? Resposta: Tecnicamente sim, com construção atômica (Image + IconButton), com o fechar acionando a bridge do app. É decisão de produto (Pesquisa e Evolução), porque pode gerar experiências diferentes no app. No caso, foi acordada a construção atômica, sem interação de arrastar.

Ref. #1208 · 08/2026

Dúvida: Os componentes nativos (ex.: alert de confirmação) vão ser equalizados com o design do Design System? Resposta: Sim, todos os componentes nativos passarão por esse processo de equalização, em levas.
